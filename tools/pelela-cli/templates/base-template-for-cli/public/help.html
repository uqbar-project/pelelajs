Pelela CLI Commands
Command Description Options Example
pelela init [projectName] Initialize a new Pelela project with the base template -T, --testing pelela init my-app --testing
pelela add <preset> Add a supported configuration to the current project testing pelela add testing
pelela new <path/componentName> Create a new component in the project --no-css, -c --component pelela new src/components/Button
pelela rename <path/componentName> <newComponentName> Rename an existing component — pelela rename src/components/Button ActionButton
pelela move <path/sourceComponentName> <path/destinationComponentName> Move a component to a destination path — pelela move src/components/Button shared/ActionButton
Note: The CLI commands are built with TypeScript and Commander.js, providing a clean interface for project scaffolding and component management.

By default, pelela new creates a <pelela> root; add -c for a <component> root meant to be used as a child.

Method Description Example
initialize() Called automatically when the component mounts. Set up initial state, start observers, or perform async setup. initialize() { this.count = 0; }

Naming Conventions

Pelela follows these naming conventions across the framework:

Scope Case Example
File names kebab-case home.pelela, home.ts, order-detail.pelela, order-detail.ts
Child component tags kebab-case <my-component>, <app-header>
ViewModel class & property names CamelCase MyViewModel, this.userName
Note: These conventions follow standard web platform practices: custom elements require kebab-case names, while TypeScript uses CamelCase for classes and identifiers.
Element Bindings
Binding Valid Tags Description Example
bind-content Any element except textarea Bind element's text content to a view model property <div bind-content="message"></div>
bind-value <input>, <textarea>, <select> Bind element's value to a view model property <input bind-value="count" />
bind-src <img> Bind element's src attribute to a view model property <img bind-src="src" />
bind-alt <img> Bind element's alt attribute to a view model property <img bind-alt="description" />
bind-class Any element Bind element's class attribute to a view model property <div bind-class="activeClass" />
bind-style Any element Bind element's style object to a view model property <div bind-style="dynamicStyle" />
bind-enabled <input>, <select>, <button>, <textarea>, <optgroup>, <option>, <fieldset> Bind element's enabled state to a view model property <button bind-enabled="canSubmit" />
if Any element Conditionally show/hide element based on view model property <div if="visible">Content</div>
for-each Any element Render a collection of items using a template <div for-each="item of items" bind-content="item"></div>
click Any element Handle click events on elements <button click="handleClick">Click</button>
enter <input> Handle Enter key press events <input enter="submitForm" />

Binding values can use dotted paths, for example bind-content="user.address.city". The same works for collections and prop-*/link-* attributes.

bind-class accepts a string, an array of strings or an object of booleans such as ['active', 'highlighted'] or { active: true }; static classes on the element are preserved.

Methods in for-each: inside a for-each, a binding can name a view model method instead of a property (except in value bindings such as bind-value and link-*, which write back, and in click, enter, for-each and index). Pelela calls it per item with a single scope object using the loop variable names as keys. The method must declare exactly one parameter. Use index="position" to expose the zero-based position.
<div for-each="product of products" index="position"> <product-row prop-product="product" prop-is-selected="isSelected"></product-row> </div>
isSelected({ product, position }: { product: Product; position: number }): boolean { return product.id === this.selectedId }

Event handlers can also target a method on the iterated item, for example click="item.remove".

Parent / Child Components

Pelela provides three attribute prefixes to communicate between parent and child components:

Prefix Direction Description Example
prop-* Parent → Child Pass reactive property values <my-component prop-name="value">
link-* Parent ↔ Child Two-way binding between parent and child <my-component link-name="name">
const-* Parent → Child Pass constant values (evaluated once, not reactive) <my-component const-name="John">
<pelela view-model="Parent"> <my-component prop-name="value" link-name="name" const-label="Hello"></my-component> </pelela>

Const values are plain literals, not expressions: text is a string, while numeric text and true / false are converted to the child property's type.

Important: All parent-child bindings must be used within a <pelela> or <component> root element, or they'll be rejected as security violations.
Toast Notifications

Use the toast service from a view model to show brief messages to the user. Toasts disappear after four seconds.

// Severity: info, success, warning, error
toast.message('Saved', ToastSeverity.success)
toast.message('Check the data', ToastSeverity.warning)
toast.message(String(error), ToastSeverity.error)
// duration: 0 keeps the toast visible until the user closes it
toast.message('No connection', ToastSeverity.error, { duration: 0 })
toast.clear()

// Default alignment for later toasts: start, center, end
toast.configure({
  horizontal: ToastAlignment.center,
  vertical: ToastAlignment.start,
})

// A toast can override the default with horizontal and vertical
toast.message('Top center', ToastSeverity.info, {
  horizontal: ToastAlignment.center,
  vertical: ToastAlignment.start,
})
Routing

Define routes as a RouteDefinition[] and start them from main.ts with router.start(root, routes).

// routes.ts
export const routes: RouteDefinition[] = [
  { path: '/', component: Home },
  { path: '/products/:id', component: ProductDetail },
  { path: '*', component: NotFound },
]

// main.ts
router.start(root, routes)

Use /products/:id for URL parameters (:id is a placeholder replaced by the actual value) and * as a catch-all route. Read the current route with router.urlParameters(), router.searchParameters(), router.currentPath() and router.currentRoute(), or navigate with router.navigateTo('/products/42').

A layout route needs children and a template with exactly one empty <outlet>. Pelela replaces it with the child page; prop-* and const-* attributes on it reach the page ViewModel.

// routes.ts
{
  path: '/',
  layout: MainLayout,
  children: [{ path: 'products', component: ProductsPage }],
}

<!-- MainLayout.pelela -->
<pelela view-model="MainLayout">
  <header>...</header>
  <outlet prop-user="user" const-app="MyApp"></outlet>
</pelela>
